# 学習目標と検証記録

## 目標

注文APIに冪等性キーと在庫管理のトランザクションを導入し、再試行や同時注文時のデータ整合性を検証する。

## 完了基準

- [ ] 新規注文と同じリクエストの再試行を実行し、レスポンスの違いを説明する。
- [ ] 冪等性キー、UNIQUE制約、商品の行ロックの役割を整理する。
- [ ] 統合テスト6件で、在庫の重複減算防止とデータ整合性を確認する。
- [ ] READMEの手順でアプリを起動し、サンプルのAPIリクエストを再現する。
- [ ] テストログと理解した設計内容を、評価の根拠資料として整理する。

## 実装済みの検証

同じキーで8件のリクエストを同時実行し、注文が1件だけ作成され、在庫が1回だけ減算されることを確認します。また、異なるキーで数量2の注文を8件同時送信し、初期在庫10に対して成功5件・競合3件・最終在庫0となることを確認します。
